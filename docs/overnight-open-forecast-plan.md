# Overnight open forecast — implementation plan

Status (2026-10-06): **Phase 1 price/session contract and Phase 2a Massive ingestion are merged.** The Phase 2b branch adds a separate 13-feature LightGBM training/forecast pipeline. No overnight artifact is selected for live use, and no API, tab, or What if replay is wired yet.

The 13 columns are the original nine in `training/overnight_dataset.py` plus four open-known model outputs: same-day Fit predicted return, Rank score, SVR predicted return, and direction-SVC margin. Historical outputs come from earlier-date same-day walk-forward models; live outputs come from the saved morning estimators. Full-universe same-day training is the default because Rank's relative scores would shift if it were trained on a tiny ticker subset. The experimental 12-ticker, June–October 2026 paid-Massive **plumbing trial** produced 909 verified labeled rows, but used only those 12 tickers for the same-day folds. In both held-out folds its gap MAE was worse than the zero-gap baseline (1.241% vs 1.225%, then 1.358% vs 1.335%). This is a working data/model path, **not evidence of a profitable overnight edge**. The trial artifact was saved only to a temporary directory. Intraday current-price and realized-volatility inputs remain out of this model until timestamp-matched historical snapshots exist; the user-entered current price can still be the `assumed_close` scenario input.

Scope: data contract and empirical check first; separate model and Overnight tab next; historical What if replay later. A weak result changes the presentation, not whether the model is retained for inspection.

## Decision this feature supports

During the trading day, answer: **"I normally sell by end of day, but if this stock closes around its current price, might holding it until the next open be better?"** This is a conditional scenario, not a claim that today's final close is known. The default comparison is against exiting by today's close at the assumed price, with explicit uncertainty about both that exit price and tomorrow's executable open. It must remain separate from Rank and Fit, whose target is today's open-to-close return (`python/stock_picker/training/dataset.py:21-48`, `README.md:157-164`).

For session *t*, define the training label as `overnight_gap_t = Open_(t+1) / Close_t - 1`, where *t+1* is the **next actual exchange session**, not necessarily the next calendar day. At inference, substitute an explicitly labeled `assumed_close` for `Close_t` and calculate `projected_open = assumed_close × (1 + predicted_gap)`. The hold-versus-exit comparison is the change from an assumed exit at that close to a possible exit at the next open, net of disclosed execution-cost assumptions; it is **not** profit relative to the original buy price. For example, previous close $10, today's open $9, and assumed close $9.50 yield a known opening gap of −10% and a hypothetical open-to-close move of +5.56%; the next open is **not** derivable from those three prices without a trained model. A predicted +2% overnight gap would imply $9.69, purely as an illustration.

This first model estimates a **close-conditioned overnight gap**. It does *not* predict the remaining intraday move. If the price changes before the real close, the user changes or refreshes the assumption and reruns the forecast. The tab has one primary forecast at the assumed close; **assumed close − step** and **assumed close + step** are subordinate sensitivity cases, not a prediction interval or three equally likely closes. Default `step` to a small fraction of the stock price, with an editable dollar step and a one-click **$0.05** option. Each case recomputes all close-derived model inputs. A future direct intraday-price→next-open model would require timestamped historical intraday observations and a different training/evaluation contract.

## Phase 1 — Lock price, session, and feature contracts with fixtures

**Implement:** Write failing data-quality fixtures first, then add a dedicated builder in `training/` that pairs row *t* with the next **observed** row for that ticker only when an authoritative exchange-session calendar confirms they are adjacent trading sessions. Drop the final row until its target open actually exists, and drop/flag any pair spanning a missing bar. For live inference, obtain the next **expected** session from that calendar; if no reliable calendar result is available, return `next_session = unknown` rather than guessing from weekdays. Follow `training/dataset.py:33-48` for an explicit label/feature contract, but create a different target and builder. `PriceStore.read(ticker)` is the local data access pattern (`python/stock_picker/storage/price_store.py:14-28`).

**Price basis:** Choose and record one basis and source policy in every model artifact. Both `Close_t` and `Open_(t+1)` must use the **same** raw or consistently adjusted basis; using `Adj Close_t` with raw `Open_(t+1)` is invalid. Refuse mixed/unknown bases and unresolved split or ex-dividend discontinuities, reporting excluded rows and reasons rather than clipping real large moves. Yahoo history is requested with `auto_adjust=False` (`python/stock_picker/ingestion/yfinance_client.py:48-55`), whereas the Finnhub backfill sets `Adj Close = Close` (`python/stock_picker/ingestion/refresh_prices.py:55-63`); their apparent columns alone do not prove equivalence.

**Feature contract:** The initial nine price/scenario columns cover prior-session close/returns and trailing volatility computed strictly through *t−1*; today's observed open and its gap versus the previous close; the assumed close and returns derived **only** from that assumption; and a session/day-of-week indicator. Phase 2b adds four open-known same-day model outputs, remaining under the user-requested 15-column cap. Use the same pure price/scenario feature builder with actual historical close values in training and hypothetical close values live, and store its version and ordered columns with the artifact. No same-day final high, low, volume, VWAP, news, or shifted full feature-parquet row. Today's news can include after-close articles (`python/stock_picker/features/news.py:3-7,91-118`).

**Verify:** The $10→$9→$9.50 example, Friday→Monday and holiday pairing, a ticker missing a valid session, duplicate/nonpositive bars, mixed raw/adjusted basis, split/dividend discontinuity, final-row target absence, and equality between historical and scenario feature construction all have explicit tests. A failing price-basis fixture must exist **before** model training.

**Do not:** Use the next open as a feature, infer exchange holidays from weekdays, reuse morning `overnight_gap` (it already requires the open), or shift the existing feature parquet and call it overnight-safe (`python/stock_picker/training/inference.py:32-78`, `python/stock_picker/features/registry.py:160-168`).

## Phase 2 — Empirical checkpoint before API or tab work

**Implement:** After Phase 1's price-basis and next-session fixtures pass, run a small standalone LightGBM experiment on that valid frame, using chronological walk-forward folds and the existing ticker holdout (`python/stock_picker/training/splits.py:19-56`; empirical experiment pattern: `python/stock_picker/training/tune_experiment.py:79-89`). Compare against (a) `predicted_gap = 0` / next open equals assumed close and (b) a ticker mean gap computed **only from each fold's training history**, with a pooled fallback for sparse tickers. This is an early measurement checkpoint, **not a promotion gate**: keep the model and feature landscape inspectable even if weak, and design the tab to say plainly when no edge has been measured.

**Evaluate:** Record sample and exclusion counts, MAE for gap and implied open, correlation, directional accuracy **alongside the observed up/down base rate**, weekday/weekend and large-gap slices, and out-of-fold residual bands. Include a costed exit-today-versus-exit-next-open comparison with explicit spread, fee, and opening-slippage assumptions for both alternatives. This is not a new buy/sell round trip: the user already owns the position. Lead with MAE against both baselines and after-cost results; a 55% direction hit rate alone is not evidence of usable edge. If there is no measured improvement after cost, report that outcome in the first sentence of the eventual UI rather than hiding or renaming the model.

**Verify:** Check that every train date precedes the test block, each baseline uses training-only statistics, residual bands use out-of-fold errors, the last unlabeled row was dropped, and changing spread/slippage assumptions changes the costed result as expected. Save a reproducible experiment summary before beginning API/UI work.

**Do not:** Run this check on unverified price pairs; use future dates in a baseline; tune on the ticker holdout; treat an after-close backtest as proof that a *midday* hold decision would have worked; or discard the feature solely because it fails an arbitrary winner threshold (`docs/adr/0004-walk-forward-and-ticker-holdout.md:13-26`).

## Phase 3 — Persist and refresh a separate overnight model

**Implement:** Train the standalone overnight regressor after the empirical checkpoint, saving a separate model name, versioned artifact, price-basis/feature contract, evaluation summary, and `latest_label_observed_at` timestamp. Copy the existing fitted-booster and atomic model-store patterns (`python/stock_picker/training/model.py:205-217`, `python/stock_picker/storage/model_store.py:34-60`, `python/stock_picker/training/main.py:259-266`). Do not call the existing `train_lightgbm` or `evaluate` unchanged: both select the day-session `LABEL_COLUMN` (`python/stock_picker/training/model.py:21-29,205-217,626-633`). Training must never overwrite Rank/Fit artifacts.

**Schedule:** The 3:30 PM CT job is **4:30 PM ET, after** the regular cash close, not before it (`docs/adr/0014-scheduled-jobs.md:12-17`, `python/stock_picker/ingestion/session.py:15-21`). Even then, today's close has no overnight label until the **next session's open** exists. Train only through the most recent observed target open; drop the incomplete last label, verify bar freshness, and keep overnight refresh separate from the Rank/Fit job until its timing is proven. Never retrain per forecast request.

**Verify:** Reloaded predictions match the fitted model; artifact metadata identifies price basis, ordered features, training cutoff, latest observable label, and experiment results; stale/missing artifact and failure-before-publish tests pass.

**Do not:** Blend overnight percentages with open→close Rank/Fit scores or use a model's feature-date range as a substitute for proving when its labels became observable.

## Phase 4 — One reusable forecast service and thin API

**Implement:** A pure scenario function accepts ticker history through the last completed session, today's observed open, `assumed_close > 0`, model artifact, as-of timestamp, and explicit execution-cost assumptions. Return `assumed_close`, predicted gap, implied next open, **gross and after-cost dollar difference versus exiting at the assumed close** (per share; optionally scaled by open shares), next expected session or `unknown`, model/version and latest-label timestamps, quote/source freshness, and the Phase 2 baseline/error summary. Add a proposed `POST /api/overnight/forecast` request/response in `api/models.py` and a thin wrapper in `api/routes.py` (existing route pattern: `python/stock_picker/api/routes.py:180-211,400-425`). Define the result independently of the UI so What if can later replay it. Include an interval or probability only if calibrated from out-of-fold observations, with methodology and sample count.

**Verify:** API tests for a valid scenario, invalid/nonfinite assumed close, missing open/price history, stale current quote, missing model, weekend/holiday/unknown next-session status, costed difference sign and units, baseline/error metadata, and fixed response serialization.

**Do not:** Label `current_price` as a confirmed close or silently use a stale quote. Existing quote summaries lack timestamps (`python/stock_picker/features/quotes.py:28-57`); add trustworthy source/as-of metadata or require the user to enter the assumed close manually when freshness cannot be established.

**Implement:** Add `Overnight` to `typescript/src/App.tsx:12-21` and mount a focused component using the established panel and API-client patterns (`typescript/src/App.tsx:70-76`, `typescript/src/api.ts:476-508`). Default the step to a small percentage of price, keep the dollar amount editable, and offer a one-click **$0.05** step. Recompute the model's close-derived features and prediction for each price rather than mechanically shifting one answer.

**Presentation:** Lead with historical MAE versus both baselines, sample count, calibrated residual band if available, and after-cost hold-versus-exit dollars. If no after-cost edge has been measured, say so plainly before the point forecast while still showing the model and historical distribution. Show next expected session, quote/model as-of times, and: “Assumes this price is today's close; remaining intraday movement is not predicted.” Keep original buying cost basis separate from the incremental exit-today-versus-hold-overnight comparison. ## Phase 6 — Historical What if replay (follow-on, designed now)

**Implement later:** Reuse the exact Phase 1 feature builder and Phase 4 forecast result to replay each historical close→next-open prediction in What if. Pin the model artifact ID **and latest label-observed timestamp** for every replay; reject any artifact containing an input or label unavailable by that historical forecast's as-of time. A feature-date range alone cannot establish this. Show actual close, predicted next open, actual next open, error, and hypothetical **costed** hold-versus-exit result. Keep these overnight rows distinct from the current morning open→close paper book (`typescript/src/whatIf.ts:81-165`, `python/stock_picker/paper/book.py:22-62`).

**Verify:** Fixture replay equals the standalone forecast for identical model/features/as-of inputs; an out-of-time test refuses future-trained artifacts; weekend/holiday and missing-next-open rows show explicit status.

**Do not:** Retrofit overnight returns into existing morning P&L totals or call an after-close replay a validated intraday strategy. Honest historical *intraday* replay is a separate future phase requiring archived timestamped intraday prices/quotes.
